# Architecture

One ASP.NET Core minimal-API project on .NET 10, one SQL Server database, one xUnit project. A second project is added only when something needs it.

```
src/Redix.Api/
  Program.cs            wiring: database, Swagger, health check, every feature's endpoints
  RedixDbContext.cs     the database and the rules every table shares
  DatabaseConnection.cs the connection string, with the user and password from REDIX_ environment variables
  Migrations/           the baseline, then one step a release, generated by EF Core (redix-api #123)
  Translations/         the words: their entities, seed and endpoint together
  Config/               the configurable values (UC-070): request and file timeouts, the VAT rate
  Auth/                 sign-in, users and permissions: users, devices, access tokens, the permission check, the system permissions and the admin's seed
  History/              the History table: its records, its actions, and the mark that keeps a secret out of it
  Projects/             projects and their units, registration and approval, and what every route that changes something in a project shares
  Structure/            what a project's entries are recorded against: categories, items, subgroups and columns, the default template, Add entry's tables
  Settings/             what a project keeps besides its structure: its payment methods
  Accounts/             where a project's money sits: its accounts and who holds them, the reconciliation, and ProjectFigures, the one owner of capital, revenue and surplus
  Partners/             a project's partners, their capital movements and shares
  Suppliers/            a project's supplier register, its search, and the rule of a VAT number
  Contracts/            what a project's contractors were promised, what the ledger holds inside each, and what remains, with their documents
  Entries/              the ledger: every entry, the details of each kind, recording, approving, rejecting and reversing, and what waits
  Revenue/              revenue entered on a revenue item, and the VAT statement built from the approved purchases
  Attachments/          a project's files: the record of each, the folder they live in, and who may read them
  Documents/            a project's documents (UC-064): any file under a name, in optional groups
  Notifications/        who was told what happened to an entry or a project (UC-036)
  Reports/              the summary, the item and contracts reports, the numbered periodic report, what waits, and their PDFs and workbooks
  Sync/                 what a phone keeps so it can work without a network (UC-030)
  Refusal.cs            the answer to a refused request: problem details with a code
  Ids.cs                how an id that may be absent travels: as text, empty when none
  StableIds.cs          ids derived from a name, so every database and migration agree on seeded rows
  Lookup.cs             a row of an enum's lookup table, LK_{enum}, which every column holding the enum points at
  Money.cs              what every amount a person types shares: two decimals and a limit
  ArabicSpelling.cs     what a search treats alike in Arabic, and the one owner of that rule
tests/Redix.Api.Tests/  one test class per feature, against a real SQL Server database, in four collections with a database each
docs/                   these pages
```

## A request

1. Kestrel receives it; errors anywhere become RFC 7807 problem details with a `code` the app translates.
2. ASP.NET Core's JWT bearer authentication checks the access token, and `SessionPolicies.CheckSessionIsOpen` checks that its device is still open. What the user holds is read for the request by `UserAccess`, which gives nothing in a project he is inactive in (redix-api #126).
3. Every endpoint falls under the `Working` policy (signed in, no temporary password to change) unless it is marked open (`AllowAnonymous`) or names another policy.
4. The endpoint, a documented static method in its feature folder, reads or writes through `RedixDbContext`.
5. The rule a request depends on lives on the class that owns the data, not in the endpoint, so the endpoint only coordinates.

## Recording an entry

Every entry, whatever its table, is recorded by `EntryRecording` through one route, `POST /projects/{id}/entries`, and changed through `PUT /projects/{id}/entries/{entryId}` (redix-api #110). The phone names the entry's id, so a second post of the same entry answers the first. The recorder finds the entry's table among the tables `EntryTable.OfferedAsync` offers the caller, the same list the picker shows, then checks what every entry shares by its item's side, then asks the table's kind for its own checks and rows. A kind is one class behind `EntryTable` (`PurchaseTable`, `ContractTable`, `RevenueTable`, `PartnerTable`); no other class asks which kind a table is.

## Rules every part follows

| Rule | Where it lives |
| --- | --- |
| Money is `decimal(19,4)`, rounding only in totals (BR-13); no VAT is stored, the VAT workbook works it out (redix-api #96, D4) | `RedixDbContext.ConfigureConventions`, `VatStatementFiles` |
| Every table has a required `rowversion`, for sync and concurrency | `RedixDbContext.OnModelCreating` |
| Ids are time-ordered GUIDs (`Guid.CreateVersion7`) made in code, never by the database | Each entity's `Id`; `RedixDbContext.OnModelCreating` |
| No NULL column: an optional value is an empty value of its own type or a row in a link table | Each entity |
| Every column holding an enum has a foreign key to the enum's lookup table, `LK_{enum}`, seeded from the enum's members: to its `Id` for a column storing the number, to its `Name` for one storing the name (redix-api #87); the permission columns wait for redix-api #120 | `RedixDbContext.HasLookup`, `Lookup`, `LookupTablesTests` |
| The API sends codes, never words; the app shows the word for the code | `Refusal.Of`, and the words in `Translations` |
| Enums travel as camelCase names, such as `active` | `ConfigureHttpJsonOptions` in `Program.cs` |
| Each environment is a name: `Dev` (dev, for automated runs, 127.0.0.1:5010, `RedixDev`) and `QA` (Muteb's own testing, 127.0.0.1:5012, `RedixQA`). Its port (`Urls`), database (`ConnectionStrings:Redix`) and admin username are in `appsettings.{name}.json`, chosen by the launch profile `dev` or `qa`, or by `--environment`; `appsettings.json` is the production base (redix-api #118) | `appsettings.*.json`, `launchSettings.json`, `DatabaseConnection` |
| Secrets come from Windows user environment variables prefixed `REDIX_`, never a file: the sign-in key (`REDIX_Jwt__SigningKey`) and, where the database signs in with a SQL login rather than as Windows, that login (`REDIX_Database__User`, `REDIX_Database__Password`). An environment's own secrets and folders come from variables prefixed `REDIX_{name}_`, which win over the shared `REDIX_` ones: `REDIX_QA_Admin__Password`, `REDIX_QA_Attachments__Folder` | `Program.cs`, `DatabaseConnection` |
| A business value someone may change while the API runs is a row of `ConfigValues` (UC-070), never a setting in a file | `ConfigValue`, `ConfigEndpoints` |
| Every action a use case names is recorded in the History table, saved with the change itself; a secret is marked `[NotInHistory]` | `RedixDbContext.AddHistory`, `HistoryRecord` |

The full data model is the pinned **Database design** issue; each use case builds the tables it needs. The database as it stands, every table, column and relation, is mapped in [Database](database.md).

## Tests

`MigratedApiFactory` starts the real API on its own database, `RedixTests`, deleted and migrated once per run, with test secrets, a test admin, and a clock the tests move forward (`FakeTimeProvider`). Every test class joins the `Database` collection, so they share that one server. CI runs the same tests against SQL Server in a container.
